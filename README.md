# 臘腸日和

一隻棕色短毛臘腸狗，一個奶油色的小家。純前端 3D 養寵物遊戲，繁體中文介面，所有寵物紀錄保存在瀏覽器。

[線上遊玩](https://hplin50643.github.io/cocoa-dachshund/) · [GitHub 原始碼](https://github.com/hplin50643/cocoa-dachshund)

## 本機啟動

需要 Node.js 22.12 以上（亦支援 24），以及 pnpm 10。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

開啟終端機印出的本機網址。可用 `pnpm dev --port 5173 --strictPort` 固定網址，避免換埠號後看不到原本的瀏覽器紀錄。遊戲需透過 HTTP/HTTPS 開啟，不使用直接雙擊 `index.html` 的 `file://` 模式。

## 玩法

- 首次進入替狗狗命名；名字可在設定修改，支援 1–16 個字素（中文及 emoji）。
- **開飯囉**：走到碗邊進食，增加飽足與心情。
- **摸摸頭**：閉眼享受摸摸、搖尾巴；也可直接點狗狗。
- **玩球球／玩玩具**：追逐目前選擇的玩具，提升心情並消耗少量精神、水分與飽足。
- **喝點水**：補充水分。
- **睡個好覺**：回狗窩睡覺，逐漸恢復精神；按「輕輕叫醒」繼續互動。
- 拖曳場景轉換視角、滾輪或雙指縮放；右上角按鈕讓鏡頭回正。
- 閒置時會呼吸、眨眼、搖尾和偶爾短距離走動。設定可減少動畫；初次領養尊重作業系統的減少動態偏好。

### 輕鬆陪伴

需求只在遊戲位於前景時緩慢變化，關閉或切到背景不扣狀態；沒有生病或死亡。每次照顧完成才計次，中途重開不會增加未完成的紀錄。

「來到家的日子」從第 1 天開始顯示，畜養總時間由領養時刻計算，包含離線；「專屬陪伴」只累計前景使用時間。設定中可查看完整領養日期及每種互動的累計次數。

### 陪伴的小約定

- 每天有餵食、摸摸及一個輪換的照顧任務；每週有五個較長的照顧目標。達成時自動獲得 XP 和親密度，錯過任務不會扣分。
- 日期依裝置的本地時間計算，每週從星期一開始。完成當日任一每日任務可累計連續照顧天數；每段連續紀錄可寬限一次漏掉的日子。
- 照顧與任務讓狗狗的陪伴等級和親密度成長；同一種照顧每天最多五次獲得互動 XP。成就涵蓋日常照顧、陪伴、時間、探索與收藏。
- 等級提升可解鎖房間、地毯、項圈、吊牌、玩具、掛畫、花盆與狗窩裝飾；在「佈置我們的小窩」選擇，立即顯示在 3D 場景中。
- 日記保留最近 100 次照顧互動。慶祝音效預設關閉，可在設定中開啟；減少動態設定會停用閒置裝飾動畫與紙花。

## 存檔與備份

- 使用 `localStorage` 的 `cocoa-dachshund:save:v1` 鍵，不建立帳號、不上傳資料。
- 互動完成及設定變更立即儲存，另每 10 秒及離開前景時保存。
- 設定 → **匯出紀錄** 下載完整 JSON；設定 → **匯入紀錄** 驗證後顯示摘要，確認才覆蓋。
- 格式版本為 `schemaVersion: 2`，保存原有的名字、時間、需求與互動紀錄，另包含任務、成長、親密度、成就、收藏裝備、日記與設定。既有 V1 本機存檔及 V1 匯入檔會自動遷移，保留原有成就和紀錄。
- 匯入上限 1 MiB。錯誤版本、損壞 JSON、缺失欄位或無效數字不會覆蓋目前紀錄。
- 本機資料損壞時提供原始檔下載；儲存權限或空間不足時明確提示，仍可匯出記憶體紀錄。
- 一次只允許一個分頁照顧，其他分頁同步顯示紀錄；支援 Web Locks 的瀏覽器使用原生鎖，其餘瀏覽器以本機寫入租約協調。關閉原分頁後重新整理即可接手；若瀏覽器無法儲存租約，遊戲會在記憶體中執行並提示匯出備份。

**不同裝置、瀏覽器、協定、主機或連接埠不會自動共享紀錄。** 清除網站資料、結束無痕工作階段可能移除存檔。從本機預覽搬到 GitHub Pages 前，請先匯出，再到新網址匯入。

## 檢查與正式建置

```sh
pnpm check
pnpm test
pnpm build
pnpm test:dist
pnpm preview
```

測試涵蓋需求上下限、任務結算、跨日及時鐘回撥、成長與成就、舊版遷移、JSON 往返、異常匯入及本機儲存失敗。正式輸出位於 `dist/`；首次載入需要取得靜態資源，沒有額外雲端 API、外部字型、CDN 或遠端模型請求。

## GitHub Pages

專案包含 [GitHub Pages 發布工作流程](.github/workflows/deploy.yml)。儲存庫的 **Settings → Pages → Build and deployment → Source** 須設定為 **GitHub Actions**。

Vite 設定 `base: './'`，建置後的 JS、CSS 與 favicon 使用相對路徑，因此可放在 `https://帳號.github.io/儲存庫/`。採單頁介面，不需要伺服器路由或資料庫。

每次推送到 `main` 都會自動發布，也可從 **Actions → Deploy GitHub Pages → Run workflow** 手動重跑。工作流程使用 Node.js 24 和 `package.json` 指定的 pnpm 10.11.0，按鎖檔安裝依賴，依序執行單元測試、型別檢查及正式建置，再驗證儲存庫子路徑下的資源；全部通過後才發布 `dist/`。`pnpm build` 已含型別檢查，因此 CI 不另重複執行 `pnpm check`。

成功後可在工作流程的 **Publish site** 或儲存庫 **Settings → Pages** 取得正式網址。同時間只允許一個 Pages 發布流程，避免部署互相覆蓋。建置工作只有程式碼及 Pages 讀取權限；發布工作僅取得 `pages: write` 與 `id-token: write`，不需要額外的個人存取權杖。

部署只上傳靜態建置成果，不包含 `node_modules/` 或任何個人寵物存檔。伺服器只提供靜態檔案，存檔仍保留在訪客自己的瀏覽器。從本機試玩搬到正式網址前，先在設定匯出紀錄，再於新網址匯入。

## 專案結構

- `src/main.ts`：介面、互動流程、計時、設定、備份與多分頁協調。
- `src/scene.ts`：Three.js 客廳、原創幾何狗狗、動畫、鏡頭、效能與資源釋放。
- `src/core.ts`：純函式遊戲規則、版本化型別、成就與驗證。
- `src/persistence.ts`：本機保存及 JSON 讀寫。
- `src/style.css`、`src/growth.css`、`src/icons.ts`：響應式設計、原創 SVG 圖示及頭像。

模型與場景全部以幾何建立，沒有第三方模型授權或外連資源需求。使用者提供的照片僅作造型參考，未包含於網站產物。需要支援 WebGL 2 與硬體加速的現代瀏覽器；3D 無法啟動時仍可開啟設定及匯出紀錄。
